# agy persistent TUI

The managed adapter uses the persistent native TUI under tmux. Startup requires shared assignment-bound initialization facts in addition to native acknowledgement; hook callbacks or transcript entries alone cannot satisfy that gate.

The Launcher runs `pc workflow orchestrator start <issue> --type <issue|epic> --provider agy --config <config>` from any ordinary conversation or terminal. Startup creates an independent agy in detached `pc-run-<full-run-id>` session, first `orchestrator-<short-attempt-id>` window. The caller's terminal remains available. Native status settings are configured before launch; names alone cannot establish ownership.

The managed instance reads its supplied Run/Attempt assignment and immutable context, writes the exact `initialization.json` fields and native ready marker, then ends its ready turn. A per-Run startup helper verifies the completed native ready reply and commits activation before sending a separate continuation message. On continuation, verify committed activation via `pc workflow orchestrator status --config <config>`. Scheduling begins only when that Run is running with this exact active Attempt. A visible prompt or callback alone is insufficient. Invalid managed context stops with an error. Launcher completion is reporting actual startup state and inspection guidance; it has no monitoring duty.

Repeat start reconnects the unfinished Run and repairs a stopped startup helper without retrying or replacing execution. Status and recovery report Run lifecycle separately from Attempt status, with cause, evidence directory and commands; attach is offered only for a verified usable terminal. Late readiness is reconciled automatically while the original execution remains live or unknown; elapsed time does not release occupancy. Inspect `startupRecovery`, `activationStatus` and retained evidence. Explicit recovery remains available through [Managed Run lifecycle](managed-lifecycle.md). Trust/login prompts and tool authorization prompts in the default permission mode require explicit user handling in the recorded terminal.

When the user requests `agy --dangerously-skip-permissions`, pass `--dangerously-skip-permissions` to `pc workflow orchestrator start ... --provider agy`. This explicit opt-in auto-approves agy tool permission requests and is persisted for all Run attempts, including children, retries and replacements. Omission on repeated start reuses the stored mode; enabling it on an existing default-mode Run rejects. Authentication and workspace trust still require user handling.

Use the managed agy adapter for named persistent roles; follow [Managed Run lifecycle](managed-lifecycle.md) for authority, acceptance, recovery and release.

1. Preflight verifies installed interactive capabilities (`--prompt-interactive`, `--conversation`, `--settings`, `--add-dir`) and tmux. Resolve missing capabilities or configuration failures before dispatch. Startup preserves its pane and Attempt on uncertainty; inspect the recorded tmux address for trust, authentication, configuration or authorization requests. Review those requests explicitly; never confirm them automatically. Completion criterion: exact native conversation identity, live exact pane and native role acknowledgement marker for the current attempt are recorded; the shared role-specific factual initialization gate must also pass.
2. For Run children (epic, worker, landing, pipeline-audit, pipeline-refactor and research-state), the adapter derives the target from the Attempt’s Run. Dispatch requires an existing `pc-run-<full-run-id>` session with matching `@pc_run_id`; children cannot create a session or select another terminal. Each child receives its own `<role>-<short-attempt-id>` window, with pane retention configured before agy starts. View the Run with `tmux attach-session -t pc-run-<full-run-id>`. Completion criterion: the saved `terminal.json` contains the exact pane address and native conversation; peer windows remain independently usable. Project-level Coordinators stay outside this Run workflow.

   For controlled child/replacement startup, initial input uses `--prompt-interactive` with a single delivered brief that includes role initialization instructions. Later messages use verified bracketed paste into the active pane. Native transcript `USER_INPUT` (with `source: USER_EXPLICIT` and `status: DONE`) and status-hook callbacks correlate turns. Submission acknowledgement alone is delivery evidence, not task acceptance. Completion criterion: a uniquely correlated native completed turn (`PLANNER_RESPONSE` with `source: MODEL` and `status: DONE`) is available to the existing receipt workflow while the agent is idle.
3. Reconnect, replacement, completion and resource release follow [Managed Run lifecycle](managed-lifecycle.md). Keep exact session ownership and all Attempt evidence available; uncertain occupancy remains reserved.

Native transcript and status-hook data are provider evidence, not the workflow's source of acceptance. Keep them available for reconciliation; missing history leaves results unknown.
