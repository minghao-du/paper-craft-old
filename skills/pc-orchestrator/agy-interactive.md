# agy persistent TUI

The managed adapter uses the persistent native TUI under tmux. Startup requires shared assignment-bound initialization facts in addition to native acknowledgement; hook callbacks or transcript entries alone cannot satisfy that gate.

Use the managed agy adapter for named persistent roles; follow [Managed Run lifecycle](managed-lifecycle.md) for authority, acceptance, recovery and release.

1. Preflight verifies installed interactive capabilities (`--prompt-interactive`, `--conversation`, `--settings`, `--add-dir`) and tmux. Resolve missing capabilities or configuration failures before dispatch. Startup preserves its pane and Attempt on uncertainty; inspect the recorded tmux address for trust, authentication, configuration or authorization requests. Review those requests explicitly; never confirm them automatically. Completion criterion: exact native conversation identity, live exact pane and native role acknowledgement marker for the current attempt are recorded; the shared role-specific factual initialization gate must also pass.
2. Initial input uses `--prompt-interactive` with a single delivered brief that includes role initialization instructions. Later messages use verified bracketed paste into the active pane. Native transcript `USER_INPUT` (with `source: USER_EXPLICIT` and `status: DONE`) and status-hook callbacks correlate turns. Submission acknowledgement alone is delivery evidence, not task acceptance. Completion criterion: a uniquely correlated native completed turn (`PLANNER_RESPONSE` with `source: MODEL` and `status: DONE`) is available to the existing receipt workflow while the agent is idle.
3. Reconnect reconciles the saved native transcript and retains the Attempt. A verified process restart uses exact conversation resume (`--conversation <UUID>`) with a new linked attempt and a correlated reconciliation instruction, without replaying its brief. `retryStage` preserves the prior conversation after verified termination; use its explicit `replaceConversation` option only for a verified unavailable-conversation reassignment. Missing conversation or ambiguous native evidence stays pending for investigation or verified reassignment. Completion criterion: exact identity is restored and predecessor output cannot satisfy the replacement Attempt.
4. Acceptance uses the common workflow gates. Unused executions receive termination; release requires verified pane absence and the recorded `agy-terminated` marker. Unknown termination retains ownership and blocks checkout reuse. Completion criterion: common cleanup and checkout release have completed.

Native transcript and status-hook data are provider evidence, not the workflow's source of acceptance. Keep them available for reconciliation; missing history leaves results unknown.
