# Claude persistent TUI

The managed adapter uses the persistent native TUI under tmux. Startup requires shared assignment-bound initialization facts in addition to native acknowledgement; input or turn events alone cannot satisfy that gate.

Use the managed Claude adapter for named persistent roles; follow [Managed Run lifecycle](managed-lifecycle.md) for authority, acceptance, recovery and release.

1. Preflight verifies installed interactive session, resume, settings, system prompt, directory and MCP flags plus login (`claude auth status`). Resolve authentication or configuration failures before dispatch. Startup preserves its pane and Attempt on uncertainty; inspect the recorded tmux address for trust or authorization requests. Review those requests explicitly; never confirm them automatically. Completion criterion: native Claude conversation UUID, live exact pane and native role acknowledgement for the current attempt are recorded; the shared role-specific factual initialization gate must also pass.
2. Initial input submits the complete single-message brief as one argument. Subsequent messages use verified bracketed paste into tmux, requiring exact native `UserPromptSubmit` acknowledgement. Uncertain delivery remains pending reconciliation; do not replay the brief or create duplicate executions. Native prompt IDs correlate `Stop` turn completions with the intended submitted brief; manual interleaved messages can coexist without false attribution. Turn completion alone is not task acceptance. Completion criterion: a uniquely correlated native completed turn (matching prompt ID and Stop event) is available to the existing receipt workflow.
3. Reconnect reconciles the saved native hooks and transcript and retains the Attempt. A verified process restart uses exact conversation resume (`--resume <conversation>`) with a new linked attempt and a correlated reconciliation instruction, without replaying its brief. `retryStage` preserves the prior conversation after verified termination; use its explicit `replaceConversation` option only for a verified unavailable-conversation reassignment. Missing conversation or ambiguous native evidence stays pending for investigation or verified reassignment. Completion criterion: exact identity is restored and predecessor output cannot satisfy the replacement Attempt.
4. Acceptance uses the common workflow gates. Unused executions receive termination requests targeting the recorded pane ID; release requires the wrapper exit record or terminated marker and independently absent or dead terminal. Unknown termination retains ownership and prevents checkout reuse. Completion criterion: common cleanup and checkout release have completed.

Native hook and transcript evidence is provider evidence, not the workflow's source of acceptance. Keep it available for reconciliation; missing history leaves results unknown. Run the opt-in real-provider check from a trusted checkout with `PC_CLAUDE_CONFORMANCE=1 pnpm exec vitest run tests/workflow/claude-conformance.test.ts`.
